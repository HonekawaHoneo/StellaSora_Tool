# 星ノ塔UI改善の実装計画

Goal: 開発目的・公式ルールの確認を先行させ、探索中の回数記録に適したUIへ整える。
Architecture: 計算モデルと保存形式を保持し、既存DOM/CSS/イベントを最小変更する。正本distと公開用docsを同期する。
Tech Stack: 静的HTML/CSS/JavaScript、Node標準テストと既存のCDPブラウザ検証。
Spec: ../requirements.json と wireframe.md、source-review.md。工程と計画の正本はハーネスとする。

## 共通条件

9ID、単価、研究の取得/使用回数、保存キー、目標保持、PC価格順を保持する。本文説明・Q&A・ツールチップを追加しない。共有Registryと色トークンは変更しない。

## 実装と検証

- [x] 開発目的・公式告知・補助資料・現行画面を調査。モデル10テスト・公開境界10テストのbaselineを確認。
- [ ] Chromium/Edgeの実ブラウザ経路で新しい寸法・全4面の文言・各入口の操作条件を記録。現行画面で新受入条件が失敗することを確認。
- [ ] design.jsonの全10原則・数値・文言を固定し、advance成功後にdistの構造とCSSを変更する。
- [ ] 集計を縦3行のまま圧縮し、十分な高さの狭幅だけstickyにする。単位・割引・研究残数11px以上、細かい印を増幅せず入力領域を保持。
- [ ] 明細小計・reset成功説明を除去し、リセット操作名と短い入力エラー/保存状態に合わせる。計算・保存・validationは再利用。
- [ ] docsへ同期、test/lint/security/browserをharness runで実行。全9操作・到達/超過/未設定・保存失敗・安全整数・境界幅・拡大・focusを検証。
- [ ] 独立コンテキストで実画面を先に観察し、10原則・copy・各寸法/ヒット領域の期待値をレビュー。指摘修正後は必要な再検証。
- [ ] ハーネスdoneとGit保存を確認する。公開・マージは行わない。

## レビュー重点

- 研究取得と支出の混同、研究上限超過した旧値の切捨て。
- 480/600/960px境界と長い数値に対する重なり・欠落。
- stickyが低い画面やキーボード操作を遮らないこと。
- reset後の目標保持、失敗保存でもカウントできること。
- 説明を名前へ偽装したり、ARIA・tooltipへ移したりしていないこと。
