# 制作判断と検証を同じ原則へ結ぶ

形式の正本は`.harness/ui-principles.md`。この表は設計と独立レビューで使い、別のチェックリスト工程を作らない。

本文の補足説明はゼロに抑える。用途から自明な説明は削除し、項目名は保つ。残る問題はレイアウト・配置全般→オブジェクト自体の見た目・サイズ→色分けの順で解決し、解決した段階で止める。グルーピング・展開折り畳み・stickyは配置の例であり、必須手法や検討範囲の上限ではない。Q&Aはこの順でも伝えられず、目的の操作に不可欠な具体的情報が残る場合の最終手段に限る。ツールチップへ説明を移すだけでは解決にしない。新旧の文言を同じ基準で再評価し、label/statusという申告や「初見・親切・正しい事実」を保持理由にしない。

| 原則ID | 作成時に決めること | 検証すること |
| --- | --- | --- |
| meaning | 対象、主操作、状態、重要度、危険性、区別 | 画面から同じ意味を読み取れるか |
| structure | ワイヤーフレーム、所属、親子、比較軸、主操作位置 | 視線・読み順・比較・操作経路が構造と一致するか |
| reuse | 既存部品、組み合わせ、バリエーションの採否、新設理由 | 実装参照、同じ役割の重複、適さない流用 |
| visual_hierarchy | 情報と操作の優先順位、必要な手掛かり | 優先順位が作業に合うか。色だけに頼らないか |
| tokens | 意味に合う実トークンと使用先 | 実定義が存在し、対象画面で使われているか |
| density_typography | 文字サイズ、行高、行の高さ・余白の用途と範囲、見える印と実操作領域それぞれの幅・高さ | 範囲自体の妥当性、小さい印で同じ操作領域を確保する代替、実測値と実起動 |
| copy | 全表示文の独立した目的・出典・代替・重複理由、object-firstの原依頼による正確な文言指定。制作委任はcopy_policy未指定の旧v3のみ | 原依頼から目的と必要性を判断し、status/labelに紛れた励まし・重複も検査 |
| states_actions | 操作と各結果、状態表示同士の関係 | 成功・失敗・取消・重複・遅延応答・フォーカス、進捗の一致 |
| accessibility | ラベル、キーボード、フォーカス、幅、拡大、読み順、対象寸法 | 実操作と対応条件での可視結果。未確認を適合にしない |
| scope_connections | 直接・関連の変更範囲、状態所有、実処理、独立境界 | 利用先への影響、保存などの実接続、仮実装と本実装の区別 |

全項目を検討する。小変更は既存定義を参照して継承できるが、適用範囲の観測は必要。非適用は具体的な理由を示し、レビューで確認する。難しい・未検証という理由を非適用に置き換えない。

新規UIは実装前のワイヤーフレームをprepareより先に変更単位のinputsへ保存する。既存UIはbefore画像と同じ条件で比較する。画面幅・テーマ・データ・拡大などの条件を記録し、重要な状態をmaskしない。

数値や全表示文はブラウザ等で測り、ハーネスの比較へ渡す。「passed」「確認した」やスクリーンショットだけでは測定値にならない。視覚の意味と文章の必要性は、実装者と別のコンテキストが実画面を先に観察して判定する。ゲートが形式を受理しても、美しさや使いやすさ、WCAG全面適合を自動証明したことにはならない。

v3では全measurement/control/copy IDへexpectation_assessmentsを記録する。実測と期待値の一致だけでpassedにしない。原依頼と画面を先に確認し、過大な印は小さな印＋同じ操作領域と比較する。モバイルや最大3件だけでは大きな印の理由にならず、一般的な状態メッセージ要求だけでは励ましの許可にならない。作業目的に反する過剰は修正指摘とし、明示された大きさ・弱視要件・正確な文言指定は確認して扱う。ブランド仕様・文章制作の委任を新規object-firstの説明例外へ読み替えない。

新規object-firstの非object文言例外は、本人が正確に指定した原依頼をauthorization_refのoriginal_brief・exact_textで参照し、scopeのpurpose・surface・target・case_idsを当該文言の全表示範囲に一致させる。一般的な状態メッセージ要件、親しみやすさ、文章制作の委任を説明文の制作許可へ読み替えない。本人の新しい明示指示が確定条件を変える場合は、その原文と対象範囲を記録して影響する上流からreopenし、実装前に再固定する。単語ごとの再承認は追加しない。詳細な形式は`.harness/ui-principles.md`を使う。

copy_policy未指定の旧v3に限り、原依頼の明示的な文章制作委任をcommissioned_copyで記録できる。原指示とpurpose・対象状態を実装前に固定し、生成文の逐語再承認は求めない。新規object-firstへこの経路を持ち込まず、ui-principles.mdの現行契約を使う。
